CODE POLICIES

Source                  Fresh TTL       Maximum TOTAL age from validation
Homepage + Program      300 seconds     3600 seconds (55 minutes stale allowance)
About                   900 seconds     86400 seconds
Podcast                 900 seconds     86400 seconds
Schedule                 60 seconds       300 seconds (4 minutes stale allowance)
Now playing              15 seconds        60 seconds (45 seconds stale allowance)

Each Data Cache entry contains validated data and its original validation time.
Warm reads/failed refreshes never advance that timestamp. Invalid content cannot
replace the good entry. After maximum age, the server rejects the expired entry;
it may recover on the next request after a background refresh finishes.

Success API payload shapes are unchanged. Failures retain existing generic shapes
and HTTP 500; expired content/open cooldown returns 503 with Retry-After. Now-playing
keeps the existing HTTP 200 {displayTitle} fallback using a neutral station label.
Its X-RPD-Valid-Until header communicates the original expiry to the player; the
client also expires old song information during network failures or hidden tabs.
All these JSON responses use Cache-Control: no-store to avoid a second HTTP cache
extending the content deadline. The internal Next Data Cache remains enabled.

The fallback uses the existing managed Data Cache, not a new durable archive.
Entries can be evicted. An empty cache plus upstream outage yields unavailable
content, not invented data. No guarantee of backup survival after cache loss.

UPSTREAM RELIABILITY

Website/Sheets: total request budget 8 seconds. Each VosCast metadata read: total
3 seconds. Maximum two HTTP attempts, including the first, inside that same budget.
Retry network/timeout errors and HTTP 408/429/500/502/503/504. Backoff 200-299ms,
or a longer Retry-After. Accepted Retry-After values are capped at five minutes;
if the delay exceeds the remaining budget, fail now and enter cooldown instead.
Malformed content and other HTTP failures are not retried. Audio is unchanged.

Three failed source refreshes (not three HTTP attempts) open a 30-second cooldown.
Provider Retry-After opens cooldown immediately, for at least 30 seconds and at
most the accepted five-minute delay. Successful validated refresh resets failures.
One pending refresh/probe is shared across route bundles in the SAME Node process,
including background revalidation. State resets on process restart.

This registry is NOT a distributed lock or distributed circuit breaker. Independent
Vercel instances/regions can miss and refresh concurrently. Warm Data Cache entries
are shared, but cannot provide atomic refresh admission. Tests explicitly reproduce
the remaining cross-instance race. WAF limits clients after activation, not global
upstream concurrency. No zero-stampede guarantee is made.

Native Vercel request collapsing is documented for ISR/image optimization, not these
dynamic API handlers. Runtime Cache has no documented atomic lock operation and is
metered; it was not added. Strict cross-instance locks or a durable backup require
a separately approved coordination/storage design. Supabase is not used for either.
